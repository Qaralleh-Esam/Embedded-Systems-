This is the real PIC16F877 TMR0 module — the same block diagram as the datasheet, animated from live silicon state, not a canned animation. Every instruction cycle (Tcy = 4/Fosc, exactly one Fosc/4 pulse) is genuinely counted: with T0CS=0 (bit5 of OPTION_REG) the left multiplexer selects the internal Fosc/4 clock; set T0CS=1 to instead count edges arriving on the RA4/T0CKI pin (toggle it above, or from the Breadboard tab's RA4 switch), with T0SE choosing rising or falling edge. PSA (bit3) routes that clock either straight into TMR0 (PSA=1, prescaler bypassed — it's servicing the Watchdog Timer instead) or through the programmable prescaler (PSA=0), whose 1:2 – 1:256 divide ratio comes from PS2:PS0 (bits2:0). TMR0 increments on every pulse that reaches it and rolls 0xFF→0x00, which sets INTCON<T0IF> — flashed red on the diagram below — exactly like real hardware; software must clear it with BCF INTCON,T0IF (the sample program does this every pass). Writing directly to TMR0 (MOVWF TMR0 / CLRF TMR0) also clears the prescaler count, matching the datasheet note that the prescaler is shared with the Watchdog Timer. Opening this tab loads a ready-to-run TMR0 demo (1:64 prescale, polled overflow advancing the PORTB LEDs — visible in the CPU State panel, or wire PORTB to LEDs on the Breadboard tab) into the code editor automatically.

Every STATUS bit is genuinely live here (an improvement on 16F84A-class demos that pin IRP/RP1/TO/PD at 0): RP1:RP0 select the active register bank below, IRP extends indirect addressing (FSR/INDF) into banks 2-3, and TO/PD reflect the last CLRWDT/SLEEP — the watchdog timer itself isn't simulated, so they never change on their own. Z, DC and C update with every instruction that affects them.

All four banks are fully live, including banks 2/3's real hardware SFRs: EEDATA/EEADR/EEDATH/EEADRH (bank 2) and EECON1/EECON2 (bank 3) drive the on-chip data EEPROM — set EEADR, then BSF EECON1,RD to read a byte into EEDATA, or load EEDATA and BSF EECON1,WREN then BSF EECON1,WR to write one (the EEPROM survives a Reset, just like real non-volatile memory — only Reassemble clears it). Everything else in banks 2/3 besides the universal PCL/STATUS/FSR/PCLATH/INTCON mirrors and the common 0x70-0x7F window is its own writable general-purpose RAM, reachable directly or via indirect addressing with STATUS,IRP set.

Logic Analyzer — 4 Channels

Time/div

Name each channel and pick any pin (any port, wired to the breadboard or not) to trace it live — captured instruction-by-instruction while running, so fast toggles aren't missed. Time/div runs from 1 ms down to 1 ns; the drawing is laid out on that real time axis (cycles × Tcy), so zooming in past one instruction's Tcy just shows a held value, same as a real instrument outrunning its sample rate. This panel is global — it keeps running under the Interrupt (RB0/INT) and SFRs & Memory tabs too, not just Breadboard — and Run/Stop here are the same Assemble & Run / Stop controls as the ones next to the code editor, so you never have to leave this view to control the simulation.

How this demo works

• The PIC drives PORTB (RB0–RB7). Each RB pin wires straight into the jumper matrix — click its L dot to route that pin to an LED, or its S dot to route it onto the 7-segment bus (bit0..7 → a,b,c,d,e,f,g,dp).
• Switches are wired to PORTA (RA0–RA5) whenever a pin is configured as an input (TRISA bit = 1) — click to toggle, read with MOVF PORTA,W / BTFSC PORTA,0. Configure an RA pin as an output instead and its switch knob turns yellow, showing the value the CPU is driving, and stops responding to clicks.
• Set TRISB = 0 before writing PORTB, otherwise the pins stay inputs and nothing lights up.
• Bank switching is real, across all four banks. Instructions only carry a 7-bit register offset — PORTA/PORTB (bank 0) and TRISA/TRISB (bank 1) share the same offset, so which one you actually hit depends on the live STATUS<RP1:RP0> bits at that moment, exactly like real hardware. Writing MOVWF TRISB while RP0=0 silently writes PORTB instead — BSF STATUS,RP0 before touching TRISx, then BCF STATUS,RP0 before touching PORTx, exactly as the default program does.
• The currently-executing instruction is highlighted directly in the Program Editor as the program runs.
